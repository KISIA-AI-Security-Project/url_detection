# 목표에 따른 입력 보완: 검증 중인 후보

목표는 접속 전 URL 판단에 필요한 구분 근거를 제한된 시간·입력 예산 안에서 전달하는 것이다. 입력 길이 증가, 테스트 통과, 바이트 감소만으로 성공을 판정하지 않는다. 동일 모델·판단 지침에서 원문과 일치하는 사실/관계/한계, 과장, 입력 토큰, 준비 및 추론 시간, 출력 토큰, 실패를 비교한다.

## f5ee1d4에서 확인된 미해결 결함

- L3가 생산한 함수 선언/정적 호출 문맥을 Builder가 감사정보로 제거했다. 직접 호출, false 분기, 미호출 함수의 실제 모델 입력이 같아졌다. 원문이 raw에 존재한다는 사실을 wire 전달의 증거로 잘못 해석한 이전 설명을 철회한다.
- 이미 inventory로 표현한 큰 입력이 토큰 한도를 초과하면 재packing에서 ValueError가 발생했다. 해당 입력은 실제 106,538토큰으로 49,152 한도를 넘었다. 예외 종류만 수정해도 입력 수용성 회귀가 해결되는 것은 아니다.

## 이번 후보의 변경과 제한

- L3는 if의 양쪽 정적 관측을 유지하면서 각 이벤트에 enclosing condition, 필요한 분기 값, Boolean literal의 해당 분기 배제 여부를 붙인다. 동적 조건은 평가하지 않고 한계를 기록한다. 실제 코드 실행이나 모든 제어 흐름의 도달가능성을 주장하지 않는다.
- Builder는 call_context를 보존한다. declaration은 선언 본문 관측, call은 정적으로 연결된 호출 분석이며 런타임 관측이 아니다.
- Builder는 확보한 script source를 소스 순서대로 스크립트당 4,000자, 전체 16,000자까지 전달한다. 이 선택은 악성 점수/정답에 의존하지 않는다. 포함량·전체량·누락 범위를 명시한다. 누락된 코드가 관측 의미를 바꿀 수 있다. 확보 원문과 이벤트 span이 정확히 대조되면 중복 excerpt 대신 해당 script와 문자 범위를 연결한다. 대조되지 않거나 원문이 잘린 경우 excerpt를 유지한다.
- 반복 evidence 행은 이름이 있는 열과 shared_facts로 표현한다. shared_facts는 재귀적으로 합쳐 읽으며, 다른 필드 구조는 별도 그룹이다. 누락을 null/음성으로 채우지 않는다. 실제 자료 선택 없이 같은 사실을 복원하는 표현 변경이다. 해석 부담의 개선 여부는 모델 실험으로 확인해야 한다.
- 문서 그룹은 반복된 E-ID 목록 대신 해당 kind를 지정한다. 원래 객체·인용 ID·원본 연결은 유지된다.
- 큰 중첩 inventory도 같은 필드 집합끼리 열을 공유한다. 서로 다른 발생을 하나로 병합하지 않고 각 행/순서를 보존한다.
- 이미 packing한 객체의 초과는 context_window_exceeded로 반환하며 추가 판단 요청을 보내지 않는다. 아직 모든 입력의 수용성을 보장하지 않는다.

## 검증 원칙

실제 native→record→wire에서 직접 호출/false 조건/미호출/호출과 조건 변경 반례를 대조한다. 파라미터 shadowing, payload 재대입, 덮어쓴 fetch, 기존 저장 자료를 유지한다. 상세 source와 audit를 코드 밖에 보존한다. 출력 검증과 인용 목록은 최종 문서에서 복원한 ID 집합을 사용한다. 실험 조건이나 Judgment 지침을 바꾸어 Builder 효과와 혼합하지 않는다. 기존 AWS 및 f5ee1d4 동결 평가 원본은 변경하지 않는다.

이 문서는 후보의 범위이며 서비스 품질 또는 전체 보완 완료 선언이 아니다.

## 독립 반례 후속 수정

feaf3eb 독립 검토에서 긴 원문의 while(false) 및 bare return 뒤 전송이 직접 전송과 같은 입력으로 남았다. loop 조건/미평가 범위와 같은 블록의 선행 종료문 문맥을 이벤트에 전달하고, 완전한 반복·블록 간 종료 흐름을 분석하지 않았음을 기록한다. 전송 관계를 삭제하거나 실제 실행을 주장하지 않는다.

inventory의 Python == 공유가 false/0, true/1, 정수/실수의 JSON 타입을 바꾸는 반례를 수용했다. 공유와 복원 검증을 JSON 타입까지 일치하는 비교로 바꿨다. 원문에 $literal 등의 압축 표식과 같은 키가 있으면 $verbatim으로 보존한다. $verbatim 내부는 압축 지시가 아닌 원문 데이터이며 변환하지 않는다. 이 수정은 모델 판단 품질 향상을 자동으로 뜻하지 않는다.

복원은 생성 당시 기록한 table_paths만 대상으로 한다. 압축하지 않은 원문이 $inventory_table처럼 생겨도 해석하지 않는다. 예약형 원문 부모의 내부는 먼저 압축하지 않아 verbatim 안에 생성 표가 남지 않게 한다. 이전 encoding의 읽기 호환 경로와 새 encoding의 명시 경로를 구분한다.

## 실제 실험에 따른 채택 상태

feaf3eb의 동일 5개 사례에서 f5ee 대비 입력 44,639→32,713토큰으로 줄었지만 평균 추론은 10.763→11.332초(출력 753→823토큰, 단일 이전 관측과 비교)였다. 큰 입력은 106,538→71,055토큰으로 줄었어도 한도에 들지 않았다. false 조건 전달은 개선됐지만 shadowing/미호출 함수의 근거 과장은 남았다. 따라서 이 표현을 전체 생산성 개선으로 채택하지 않는다. 타입·제어 문맥 후속 수정은 로컬 재검증이며 새 모델에서의 품질/속도 검증을 대신하지 않는다.
